# Phase 9 (MCP Engine) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Normalized cross-agent MCP inventory (transport/command/args/url/env-count/status) with secret-safe collection, DB persistence, and IPC.

**Architecture:** New `mcp` module (model + normalize + persist). Adapters gain an additive `mcp_details()` trait method (default `Unsupported`; Phase 5 name-only `mcp_servers()` untouched) returning rich per-source detail; the engine maps detail → `McpServer` rows (id `{agent}:{name}`, status Configured/Offline/Unknown — never Connected without liveness), persists via replace-per-agent in a transaction, and serves reads from the DB.

**Tech Stack:** Rust 2021, serde_json (present), std only.

**Spec:** `MASTER_PLAN.md` §19 (model, statuses, env-count rule).

## Global Constraints

- Env VALUES never read anywhere: Claude/OpenCode count `env` object keys; Codex has no env data (headers only). Tests pin canary absence.
- Args pass through capped (≤32 entries, ≤256 chars each) — user-owned local config shown to its owner; env secrets stay hidden. Rationale ledgered; Phase 21 audits.
- Status is never `Connected` (no liveness probe exists); Configured = enabled-or-unknown, Offline = explicitly disabled, Unknown = headers-only.
- Schema changes only via numbered migrations (`005_mcp_details.sql`: `ALTER TABLE mcp_servers ADD COLUMN args TEXT; ADD COLUMN env_count INTEGER NOT NULL DEFAULT 0`).
- Replace-per-agent persistence (delete + insert in one transaction) — refresh is idempotent, no duplicates.
- No git — no commit steps; ledger is the record.
- Verification per task: `cargo test --lib` in `agenthq/src-tauri` (exit 0). MSVC-prefixed PATH required. (`cargo test --bin agenthq` harness OS-blocked; gate uses `--lib`.)
- Fixtures extend `fixtures/{claude,opencode,codex}/` (new files only; existing ones untouched).

## Review Focus

- An `env` VALUE in any fixture must never appear in normalized output — Task 1 pins `test_claude_env_values_hidden` (canary in fixture entry env).
- A malformed MCP entry (non-object, wrong types) must be skipped, not fatal — Task 1 pins `test_bad_entry_skipped`.
- Double refresh must not duplicate rows — Task 3 pins `test_refresh_is_idempotent` (refresh twice → same row count).
- No output row may carry status Connected — Task 3 pins `test_no_connected_without_liveness`.
- `args` beyond caps must be cut — Task 1 pins `test_args_capped` (40 args + 300-char arg → 32 + 256).

**Interfaces:**
- Consumes: Tasks 1–2 detail methods
- Produces:

  - `pub fn normalize(agent_id: &str, source: &str, details: Vec<McpServerDetail>) -> Vec<McpServer>` — id `{agent}:{name}`, status from enabled (Some(true)→Configured, Some(false)→Offline, None→Unknown... wait: Claude no-lists case → enabled None → Unknown, but spec says Configured default. Rule: None → Configured EXCEPT Codex headers-only → Unknown. How does normalize know? Add param? Decision: `McpServerDetail.enabled: Option<bool>` None means "no info" → engine maps None → Configured, and Codex passes... Codex has no info either → Configured too. Hmm — then Unknown never occurs; drop Unknown? Spec lists Unknown status. Codex headers-only IS the Unknown case (transport unknown, liveness unknown, enabled unknown). Decision: Codex sets a `source` that maps... cleaner: engine takes `default_status: McpStatus` per call site: Claude/OpenCode → Configured, Codex → Unknown; explicit disabled → Offline always wins. So `normalize(agent_id, source, default_status, details)`.
  - `Db::replace_agent_servers(&self, agent_id: &str, servers: &[McpServer]) -> Result<(), String>` (DELETE + INSERT in transaction), `Db::list_mcp_servers(&self, agent_id: Option<&str>) -> Result<Vec<McpServer>, String>`
  - `refresh_mcp(manager, db)` command: for each adapter id with mcp capability... manager doesn't expose adapters' details generically — needs downcast. Decision: refresh implemented per known adapter in lib.rs (match adapter id → construct adapter? adapters need home...). SIMPLER: `refresh_mcp` takes no adapter access — instead each adapter's details are collected at... Hmm. Manager holds Box<dyn AgentAdapter> behind Mutex; trait has mcp_details() default! So: `manager.lock().adapters_details_mcp()` — add manager method `collect_mcp(&self) -> Vec<(String, CapabilityResult<Vec<McpServerDetail>>)>` iterating adapters calling mcp_details(). No downcast needed. Add in Task 3 (manager.rs + test).
  - `get_mcp_servers(db, agent_id: Option<String>)` reads DB
