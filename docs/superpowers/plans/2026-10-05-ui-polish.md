# UI Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Professional motion + icon polish without touching spec §3 tokens or any Rust code.

**Architecture:** lucide-react icons (spec §4 sanctions Lucide) paired with text; one orchestrated page-enter moment plus action-answered motion only; skeleton loaders replace "Loading…" text; `prefers-reduced-motion` kill-switch; running-dot pulse is the single lively element.

**Tech Stack:** React 19, lucide-react (installed), hand-rolled CSS in `theme.css`.

**Spec:** `MASTER_PLAN.md` §2 (design language), §3 (tokens — unchanged), §36 (accessibility).

## Global Constraints

- Tokens (§3 hex) unchanged. No new palette.
- Every icon `aria-hidden="true"`, always paired with visible text except the dialog close (has aria-label).
- `prefers-reduced-motion: reduce` disables all animation/transition.
- tabular-nums for metric values and data tables (numbers stop jittering).
- No git commits.
- Verification: `npx tsc --noEmit` + `npm run build` in `agenthq/` (exit 0). No Rust changes, so no cargo gate.

## Review Focus

- An icon-only button must still have an accessible name — pin by code read (only dialog close, has aria-label).
- Skeletons must expose a screen-reader status, not silence — Skeleton component carries role="status" text.
- Reduced-motion must kill pulse + shimmer + transitions — single media query block covers all.
- Page-enter animation must not re-trigger on every event refresh — key is on page identity only, not data.
- Dark theme must keep contrast on muted text + info buttons — tokens already checked, no new colors.
